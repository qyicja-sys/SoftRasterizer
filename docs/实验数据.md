## 8. 结果观察

- **整体性能**：在模型测试中 triangle_2 最快（10.66 ms，相对倍数 1.00）；triangle_1 最慢（45.49 ms，4.27 倍），triangle_4 次之（43.44 ms，4.08 倍）。
- **triangle_1 的开销来源**：每个扫描行都新建 `std::vector` 保存两条边的交点，并逐行做三次求交运算，容器分配与交点计算的开销显著，因此耗时与分配次数均偏高；在细长三角形测试中分配次数达到 1600022 次。当前实现已不再使用 Bresenham 描边。
- **像素一致性**：triangle_3_1、triangle_3、triangle_4、triangle_5 与基准 triangle_3 完全一致；triangle_1 有 40 个差异像素（填充边界采用闭区间取整，且交点数量不为 2 的扫描行会被跳过），triangle_2 有 2572 个差异像素（右边界采用半开区间，少填充一列）。
- **分辨率与内存**：画布边长从 256 增至 2048（像素数增至 64 倍），内存峰值从 506.24 KB 增至 24.12 MB（约 48.79 倍），接近平方增长；三角形数据（117.70 KB）在各档保持不变，增长主要由帧缓冲与校验图像贡献。
- **三角形数量与内存**：数量从 100 增至 10000（数据从 2.34 KB 增至 234.38 KB，约 100 倍），内存峰值仅从 6.01 MB 增至 6.23 MB（约 1.04 倍），说明此时固定开销（1024 x 1024 帧缓冲与图像）占主导。
- **三角形大小与内存**：三角形数量固定为 200、数据量固定为 4.69 KB，三档峰值均为 6.01 MB，说明单个三角形的覆盖面积不影响内存占用，只影响耗时。
- **形状与内存**：退化为 20000 个共线三角形，被背面剔除直接丢弃，因此仅分配 22 次、耗时最低；等边与细长形状的耗时差异主要来自扫描范围与像素覆盖。
- **内存泄漏**：五组测试的泄漏检测结果均为 0 B，运行期临时对象（帧缓冲、校验图像、路径字符串等）均正常回收。

## 9. 结论

1. triangle_2 的扫描线 + 线性插值实现在当前测试条件下综合性能最好。
2. 内存占用与画布分辨率近似平方相关；三角形数据量增长对总内存影响较小，因为帧缓冲与校验图像占据主要固定开销。
3. 所有实现均未发现内存泄漏，内存管理正确。
4. triangle_1、triangle_2 与其他实现的像素差异来自填充边界取整与退化扫描行处理策略不同，可在需要时统一取整策略以对齐输出。

| D | 小数屏幕坐标 | 增量计算（double） | 验证精度改善效果 |

### 10.8 结果观察

- **耗时**：A（int 增量）与 D（double 增量）接近，B（float 增量）略慢，C（逐像素直接计算）明显最慢。模型组 C 的平均耗时是 A 的 7.51 倍，说明每像素重新计算三个面积的开销远大于增量累加。
- **像素一致性**：A 与 B/C/D 相差 19272 个像素（约占非黑像素的 9.9%），差异来自把小数坐标截断成整数的取整误差；由于每个三角形使用不同颜色，遮挡交叠处的颜色差异也被计入。B、C、D 三者完全一致，说明在 1024 画布、5022 个三角形的场景下，float 增量的累积误差没有改变任何像素的覆盖判定。
- **精度改善**：D 相对 B 没有产生额外的像素差异，也没有明显变慢；本轮场景中 float 增量已经足够，double 增量的收益主要是更大的数值余量，而不是可观测的画面改善。
- **分辨率**：耗时随像素数增长而上升，2048 x 2048 时 C 达到 444.52 ms，约为同条件 A 的 8.2 倍；B 与 A 的差距也随分辨率增大（74.45 ms 对 54.42 ms），float 运算与整数运算的差异被放大。
- **数量**：10000 个三角形时 A 26.07 ms、C 164.91 ms，增量实现优势明显；1000 个时 A（4.12 ms）略高于 B（3.07 ms），属于 3 轮测量下的正常波动。
- **大小**：三角形越大，逐像素开销占比越高；大三角形 C 为 146.22 ms，是 A（16.99 ms）的 8.6 倍，与单个三角形覆盖面积增大一致。
- **形状与退化**：退化组出现明显异常。A 截断到整数坐标后三点严格共线，面积为 0，1.59 ms 内全部丢弃；B/C/D 保留小数坐标，浮点舍入使“退化”三角形的面积不再严格为 0，部分三角形未被剔除，仍然扫描 400 x 400 的包围盒，导致 B 728.38 ms、C 9154.84 ms、D 805.03 ms。这说明小数坐标下退化判定需要合适的容差，不能只与 0 比较。
- **内存**：五组均无内存泄漏；峰值主要由帧缓冲与校验收图决定（2048 x 2048 达 24.23 MB），三角形数组本身为 235.41 KB（模型）到 937.50 KB（20000 个退化三角形）。

### 10.9 结论

1. 覆盖判定方面，B（float 增量）已与 C（直接计算）、D（double 增量）完全一致；D 的精度改善在本场景中未转化为可观测的像素差异。
2. 增量实现（A/B/D）明显快于逐像素直接计算（C），模型场景约 6~7.5 倍；三角形越大、分辨率越高，差距越明显。
3. A（整数坐标）速度最快，但与小数坐标实现存在约 1.9 万像素的边界差异，只适合验证旧环境，不应作为摄像机管线的最终方案。
4. 退化三角形在小数坐标下会因浮点误差逃过“面积等于 0”的判定，产生大量无效扫描；后续应加入与三角形尺寸相关的容差，或先按包围盒/边长做预筛选。
5. 五组测试均未发现内存泄漏，内存管理正确。
